# Repository names, implemented capabilities, and shared adapters

The application resolves the current point, exposes connected source relationships, and lets a person select a transform. A generated adapter is a local interface; execution requires a real runner or reachable provider. There is no score, recommendation, consensus threshold, or promotion gate in this navigation path.

`src/lib/repository-registry.json` is the source map consumed by the application. It preserves GitHub repository IDs, current names, upstream aliases, runtime identifiers, pinned commits, inspected paths, and activation requirements. Names describe intended roles; the implemented column describes the source actually inspected. It is not a deployment inventory.

The default screen replaces the old Canon Bind assessment. Historical catalog, assessment and persisted binding records remain in source and browser storage; they do not control the adapter screen. No source repository is archived or deleted by this reshuffle.

## Runtime connections

- Local runner: the JavaScript modular-factorial operation from `wasm-js-ATBASH-omni-plexing` is exposed as a local transform. Its origin is Sylwia Lask's `wasm-js-bench`. The WASM, matrix and image benchmark paths remain in their own repository.
- HTTP runner: configure an endpoint implementing `POST { capabilityId, input, source } → JSON result`. Browser CORS, provider authentication and provider behavior remain the connection's responsibility. No credentials are embedded in generated modules.
- Generated adapter: downloads an ESM module carrying a source-pinned contract and `connect(run).invoke(input)`. It needs a supplied runner, and does not create an external service.
- Events: each execution records source coordinates, old/new points, outcome and script input in browser-local history. Provider failures retain the original point. The history is an execution record, not signed attestation. Export retains all recorded entries; the UI shows the last eight.

## Preserve installation contracts

Renaming a GitHub repository does not rename its exported functions, Python package or Roundcube plugin class. Roundcube folders must keep `contextmenu`, `elasticlayouts`, `globaladdressbook`, `taskwatermark`, `swipe`, and (for the legacy implementation) `markasjunk2`. `DoodleShades` inherits the `elastic` skin. `roundcubemall` is an older Roundcube snapshot; newer plugin forks require version compatibility checks in the target mail installation. Cross-repository edges indicate source relationships, not a tested deployment.

`ContactResumes` remains the `skill-seekers` package with `skill_seekers` imports. Its MCP compatibility shim points to `python -m skill_seekers.mcp.server_fastmcp`. Java chat needs a TCP bridge to enter the browser; GPU and camera capabilities retain their browser/device requirements.

## Changes and validation

The source registry, typed resolver, adapter runtime, local transform, and default UI form one composition in `systemsNxXD`. `XDcomms` retains its current code and links to this composition through stable source identity. Separate repository IDs remain separate even where inspected files share hashes.

Run `npm ci`, `npm test`, `npm run typecheck`, and `npm run build`. The PR also includes small pre-existing build-check repairs: JSDoc for the PWA helper, safe rendering of unknown errors, and isolated head-injection test fixtures. Platform branding and preview bridge are preserved.
