## Corrected scope and authorization

The user's explicit instruction is to **collapse all work from all project threads into one cumulative, functioning model**. Separate threads, implementations, site surfaces, hardware experiments, graphics, historical structures, mathematical structures and applications must become **typed capabilities and relationships within ONE model**, not a set of rival architectures.

The original objection was to dropping functions, provenance, distinctions, and context as a side effect of simplification. It was **not** an objection to unification. Every new observation extends what is already present. Do not build another replacement core when the current owner can extend.

## Existing canonical runtime

Retain the system's current contract:

```
CURRENT POINT
  → RESOLVE CORRELATE SPACE
  → ENUMERATE AVAILABLE AVENUES
  → EXPLICIT CALLER SELECTION
  → INSTANTIATE SELECTED TRANSITION
  → RECORD NEW POINT AND SCRIPT
  → CONTINUE
```

The coordinate resolver only exposes available avenues; it does not score, rank, recommend, approve or deny them. Permissions and external authorization occur at separate adapters, not in the coordinate enumeration. `systemsNxXD` owns this traversal and GoldenEvent; `XDcomms` and domain services are consumers. No second authority is introduced here.

### New observation: addressed midpoint

Each new observation has incoming history, present context and potential outgoing continuations. `midpoint` means its place in an ongoing relationship; it does **not** claim that any numeric coordinate is the arithmetic halfway point. `Hofstadter torus` is a named proposal, not a completed coordinate derivation. ## ONE model: capabilities, sources and projections

1. **SOURCE / occurrence:** exact content hash when bytes were read; source locator, original words, timestamp/coordinate, authorship and rights when known. Equal bytes may deduplicate, but every occurrence and its coordinate survive.
2. **ALIAS / correction:** attach each typo, voice variant or alternate spelling to the precise source coordinate. Never globally overwrite original wording.
3. **TYPED STRUCTURE:** retain symbolic, mathematical, historical, physical, computational and visual types as distinct relations in the SAME model. Any equivalence must have its own evidence and derivation.
4. **REUSABLE CAPABILITY:** each discovered function gets input contract, output contract, adapter stub/implementation reference, host requirements and evidence state. Existing verified implementations take precedence over rebuilding.
5. **RELATION / HYPERGRAPH:** a claim's provenance, context, service purpose, dependencies, contributing threads, surface projections, and source ownership remain traversable.
6. **SELECT / ACT / RECEIPT:** use the existing canonical selection and event contract; an execution digest proves recorded-byte integrity, not actor identity, authorization or physical truth.
7. **RETURN / SERVICE:** each useful action routes back to a person, device, workbench, community, or next addressed point. Reciprocal practical assistance is a first-class system objective.

## Mandatory evidence and safe merging

Evidence states must distinguish: source observed; extracted; specified; code located; implemented; test executed; independently reproduced; external outcome verified; public-ready; unresolved. A generated illustration, a committed file, a hash digest, and a measured result are different claims.

A source merge must be monotonic with respect to **information preservation**: never lose a unique function, source occurrence, alias coordinate, relation, or contradictory assertion. Reconcile contradictions with explicit review instead of quietly deleting them. Preserve upstream licenses and privacy restrictions. Don't rewrite historical source code, delete TS/TSX files or publish private connector archives as part of automatic consolidation.
